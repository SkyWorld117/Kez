# User Configuration Format

This document describes the format for user configuration files. These files are generated by the system per user request for (typically) one package in YAML format. They are used for very precise control over the package configuration including its dependencies, build options, and properties.

## User Configuration Structure
The user configuration files follow a similar structure to the general configuration format but are tailored for specific user needs. The structure is defined as follows:

```yaml
cheese:
  <package_name>:
    description: <package_description>
    version: <package_version> # default is latest
    build:
      configurations: <configurations_list> # If exists in the original package
      stages: <stages_list> # If exists in the original package AND the stages are configurable

  <dependency_name>:
    description: <dependency_description>
    version: <dependency_version> # default is latest
    build:
      configurations: <configurations_list> # If exists in the original package
      stages: <stages_list> # If exists in the original package AND the stages are configurable

  <another_dependency_name>:
    description: <another_dependency_description>
    version: <another_dependency_version> # default is latest
    build:
      configurations: <configurations_list> # If exists in the original package
      stages: <stages_list> # If exists in the original package AND the stages are configurable

  ...

recipe:
  abstract_packages: # Optional, if the user has selected abstract packages
    <abstract_package_name>: <selected_abstract_package_name>
    <another_abstract_package_name>: <selected_abstract_package_name>
    ...
  dependencies: # Must exist, contains at least the target package
    - <dep_1>
    - <dep_2>
    - ...
```

Users are supposed to modify the values of the entries, but not to add/remove any entry.

## Local Source Override
For software developers, it is often desirable to test the installation of a package using a local source directory instead of fetching the source code from the remote repository. To achieve this, users can simply set the `version` entry to the absolute path of the local source directory. For example:

```yaml
cheese:
  my_package:
    description: My package description
    version: /path/to/local/source/directory
    build:
      configurations: <configurations_list> # If exists in the original package
      stages: <stages_list> # If exists in the original package AND the stages are configurable
```
