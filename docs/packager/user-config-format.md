# User Configuration Format

User configuration files are generated by Kez for precise control over a package's build
including its dependencies, build options, and properties. They are YAML files that the
user edits before installation.

## Structure

```yaml
kez:
  <package_name>:
    description: <package_description>
    version: <package_version>         # default is latest
    compiler: <compiler_spec>          # e.g., "system", "gcc@13.4.0" _(optional)_
    patches:                           # _(optional)_ — defined in the database recipe
      - name: <patch_name>
        enabled: true | false          # default is false
    build:
      configurations: <configurations_list>
      stages: <stages_list>

  <dependency_name>:
    description: <dependency_description>
    version: <dependency_version>
    compiler: <compiler_spec>          # _(optional)_
    build:
      configurations: <configurations_list>
      stages: <stages_list>

  ...

recipe:
  abstract_packages:
    <abstract_name>: <selected_implementation>
  dependencies:
    - <dep_1>
    - <dep_2>
  targets:
    - <target_package>
```

Users should modify values of the entries but should not add or remove entries.

Pre-built example configuration files live in the `archive/` directory. These demonstrate
the full format including compiler selection per-package, abstract package resolution,
and build option overrides.

## Generated Toolchain Options

For Autotools and CMake packages, the generated `build.configurations.options` section
includes standard options even when the database did not explicitly list them.
These are ordinary user-configurable options:

| Option | Description |
|---|---|
| `CFLAGS` / `CXXFLAGS` | Compiler flags |
| `LDFLAGS` | Linker flags |
| `CMAKE_C_FLAGS` / `CMAKE_CXX_FLAGS` | CMake language flags |
| `CMAKE_EXE_LINKER_FLAGS` | CMake executable linker flags |
| `CMAKE_INSTALL_PREFIX` | Install prefix |

Default values use `${}` templates like `${package.prefix}`, `${dependency.includes}`,
`${dependency.ldflags}`, and `${dependency.libs}`. The parser resolves these when
generating shell commands.

`CMAKE_PREFIX_PATH` and Autotools `LIBS` are not generated by default; if either appears,
it was declared explicitly by the package database.

## Local Source Override

To test a package using a local source directory instead of fetching from a remote:

```yaml
kez:
  my_package:
    description: My package description
    version: name@/path/to/local/source/directory
    build:
      configurations: <configurations_list>
      stages: <stages_list>
```

The `@` sign signals to Kez that the path component is a local directory. This allows
developers to test uncommitted changes or custom builds without pushing to a remote.
